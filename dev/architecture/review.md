| 修正照里程碑滾動進行，每個 commit 先停下來給使用者看、同意才 commit | 使用者要每個 commit 能獨立、看得出重點 |

## 踩過的坑

- **提案搬檔前沒對照舊定案**：M2b 把 `llm_service` 搬進 `llm/`，和 09-29 的資料夾定義相反，只好退回。錯在把頂層資料夾當成一層；搬檔前先查舊定案。
- **吞掉取消的任務殺不死，測試會卡住而不是紅**：B7 突變卡了一小時。測試的假 sleep 看到 `current_task().cancelling()` 就丟例外，這類突變才會乾淨地紅。
- **突變沒套上也會跑出全綠**：M4b 的突變腳本第一版用 shell 字串拼 Python，13 個突變沒套上就跑測試、全「綠」。改成套不上就算失敗。
- **突變副本別複製整個 `src`**：裡面有 30 GB 的 Telegram 媒體，`docker cp` 卡了 16 分鐘；改成 `git archive` 只取追蹤的檔，一個突變約 4 秒。
- **守衛的寫法會漏抓**：用 regex 寫的路徑守衛，字串在比對前就被遮掉，突變全綠才發現，改成 AST；`X.read_text(encoding=…)` 沒有位置參數，被 finder 的 `not node.args` 跳過。
- **測試的備份寫進了正式 `/logs`**：`panel_bump` 測試用暫存路徑寫檔，備份卻進了 `/logs/runtime_backup/`。`test/__init__.py` 把 `RUNTIME_BACKUP_DIR` 指到暫存目錄；那 3 個檔經使用者同意才刪。
- **模組層的賦值寫在 import 前面，整組指令消失**：`user_commands` 在 import `settings_file` 之前就用到它，`/list_item_price`、關鍵字監控整組不見。沒有測試 import 這個模組所以沒抓到；新守衛把 `commands/*`、`music/*` 實際 import 一遍。
- **啟動 gate 首輪偶發紅**：靠真實時間的測試在啟動負載下翻車，每次多等約 100 秒；gate 跑的時候也別在同一台機器並行跑測試副本。
- **改 compose 的 command 要重建容器**：`docker restart` 吃不到新的 command，要 `docker compose up -d discord-bot`。
- **暫存區是使用者邊看邊暫存的紀錄**：當成過時快照 `git reset` 掉 18 個檔，使用者後來自己重做一輪。不要動暫存區。
- **`git commit -- src` 會把被追蹤的狀態檔掃進去**：`music_runtime.json` 早就被追蹤，`.gitignore` 不生效。commit 一律列明確檔名。
- **寫完的檔被編輯器蓋回去**：10-13 寫過一次、程式也印了成功，檔案卻回到舊內容，疑似使用者開著的 IDE 用舊緩衝蓋回。寫完要重讀驗證，使用者開著的檔要提醒重新載入。
- **報告沒查 log，分不出哪些真的發生過**：第三輪報告的 B3～B6 實際 0 次，反而漏了三件真的出過事的。
- **巴哈開串後沒馬上記下**：續文、附圖、留言都送完才記，中途 Discord 500 就沒記，下一輪再開一串；04-30～09-30 共開了 250 個不完整的串。
- **公告推送與保險輪詢沒有共用鎖**：兩邊各用一個監看物件，去重只靠送完才寫的紀錄，10-17 同一篇隔 2 秒各送一次。
- **連線借出前沒檢查還活不活著**：三處各自 `PGVectorStore.from_params`、沒有 `pool_pre_ping`，資料庫關掉閒置連線後第一次使用必失敗；疊上「先刪再寫」，09-17、09-24 兩筆偏好永久丟失。
- **改 requirements 要兩個映像一起建**：search-mcp 和 discord-bot 是同一份 dockerfile 建的兩個映像，只建一個會讓套件版本一新一舊。
